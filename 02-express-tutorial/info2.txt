And another thing that u need to keep in mind is the
304 Not Modified status.

why does this happen??
Possible Reasons for 304 Not Modified:

1.  Client-Side Caching:

The browser is sending an If-Modified-Since or
 If-None-Match header in the request.
The server sees that the resource hasn't 
changed and responds with 304 Not Modified
 instead of 200 OK.


2.   Middleware or Proxy Interference:

If you have a proxy or middleware handling requests before
 your Express app, it might be modifying the response.

3.  No Explicit Cache-Control Headers:

Express may automatically handle conditional 
requests based on caching headers.

let sortedProducts = [...products]

[...products] takes all elements from products 
and puts them in a new array.

This ensures sortedProducts is a separate array
 from products, meaning modifying sortedProducts 
 won’t affect products (but only at the top level).

on browser: http://localhost:2006/api/v1/queryful?search=a&limit=4
app.get('/api/v1/queryful',(req,res)=>{

    let sortedProducts = [...products]

    if(search){

middleware in express js : functions that execute during the 
request to the server.

// req => middleware => res 
each middleware has access to request and response object.

middleware is literally everywhere in express

explanation: 

const express = require('express')
const app = express()

app.get('/',(req,res)=>{
    const method = req.method
    const url = req.url
    const time = new Date().getFullYear()
    console.log(method,url,time)
    res.send("Home")
})
app.get('/about',(req,res)=>{    
    res.send("About Pages Baby")
})


app.listen(2006,()=>{
    console.log("Server is listening on your bday port")
})


See in the url / , we have mentioned some things like
url, time, method : but what if we want to do the same for
the other urls like /about, /king etc etc.
repeating the same code is not ideal. what to do now?

u can do this:
put that code in a function and use that function.
Example:

const express = require('express')
const app = express()


const logger = (req,res,next) => {
    const method = req.method
    const url = req.url
    const time = new Date().getFullYear()
    console.log(method,url,time)
    next()
    //next() is a function in Express middleware 
    // that passes control to the next middleware
    //  function in the request-response cycle.
    //If you don’t call next(), 
    // the request hangs because it never moves forward to
    //  the next middleware or route handler.
}
app.get('/',logger,(req,res)=>{
    res.send("Home")
})
app.get('/about',logger,(req,res)=>{    
    res.send("About Pages Baby")
})


app.listen(2006,()=>{
    console.log("Server is listening on your bday port")
})

routes that have /api at the beginning

app.use([logger,authorize])

meaning logger first then authorize

const authorize = (req,res,next)=>{
    const {user} = req.query
    if(user){
        req.user = {name: user, id:Math.floor(Math.random()*100)}
        next()
    }else{
        res.status(401).send("Unauthorized")
    }
    
}
module.exports = authorize


//in any of my routes, I can use the req.user
app.get('/about',(req,res)=>{ 
    console.log(req.user);
    res.send("About Pages Baby")
})
